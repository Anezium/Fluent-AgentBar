## Dependency notes

- 001 comes first because the WinUI app has fragile parsing, config, process,
  and Windows interop logic with no C# test project or CI baseline.
- 002 depends on 001 because quarantining the C++ legacy path should not happen
  until the WinUI path has its own build/test command.
- 003, 004, and 005 can be implemented independently after 001.
- 006 depends on 004 because multi-widget ownership and recovery are harder to
  reason about if multiple app instances can create overlapping widgets.
- 008 depends on 002 because docs should describe the chosen canonical direction,
  not re-document the transitional state.

## Findings considered and rejected

- Full visual redesign: rejected for now. `AGENTS.md` and
  `docs/design/fluent-windows.md` already require Windows Fluent patterns; the
  highest leverage work is verification, correctness, and removing legacy
  dependency.
- Removing all C++ files immediately: rejected as a first step. The legacy app
  still contains historical behavior and parser references; deleting it before
  WinUI tests and docs are canonical increases risk. Plan 002 makes it
  non-authoritative first.
